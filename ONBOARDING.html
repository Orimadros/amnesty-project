What the paper is about

This is deliberately concise. The point here is to anchor the repo work, not replace reading the paper.

The policy

Brazil legalized some illegal occupation of Amazon public land

In 2009, Programa Terra Legal offered a path to legal ownership for some land-grabbers occupying federal undesignated land in the Amazon. The key eligibility rule was roughly: occupation by 2004 and parcel size up to 1,500 hectares. In 2017, eligibility became more generous: occupation up to 2011 and areas up to 2,500 hectares .

The tension

Formalization might help, or it might create moral hazard

Supporters argued legalization could reduce conflict and improve enforcement: if a parcel has a legal owner, environmental rules can bite. Critics argued that forgiving past land grabbing tells people that future land invasions may also be forgiven .

Main unit

Rural parcels

The paper studies land parcels, mostly built from CAR property claims. A CAR is not necessarily a legal title. It is a self-reported rural property boundary, which is useful but messy because claims can overlap or be inaccurate.

Main outcome

Deforestation and occupation

MapBiomas classifies land cover for 30-by-30 meter satellite pixels. The project uses those pixels to identify legacy forest, when a parcel first shows human occupation, and how deforestation changes over time.

Other outcomes

Prices, titles, applications, fines

The paper also studies land prices, amnesty applications/titles, and environmental fines. Those help interpret whether markets believed another amnesty was likely and whether behavior changed after 2009 .

Groups in plain English

The paper keeps comparing types of parcels

Eligible: target land, occupied by 2004, under 1,500 ha Ineligible: target land, but too late or too large Never eligible: protected/control areas Already legal: titled before the policy Treated: eligible parcels that applied or received title

The central empirical question is not only "what happened to eligible parcels?" It is also "what happened to ineligible parcels after people learned the government might forgive land grabbing?" That is why the repo has to carefully assign parcels to policy groups .

Concepts you will need

This section is the bridge between "I can read the paper" and "I can safely work on the migration."

Pipeline

A pipeline is the ordered set of steps that turns inputs into outputs. In this project: raw shapefiles and spreadsheets become cleaned spatial layers, then parcel classifications, then outcomes, then regressions, then paper figures.

DAG

DAG means "directed acyclic graph." Plain English: a flowchart where arrows point from prerequisite to result, and there are no loops. It matters because the computer can know what must run before what. If table B needs file A, the DAG says so explicitly.

Docker

Docker is a sealed, reproducible mini-computer. Instead of trusting whatever R/GDAL/spatial libraries happen to be installed on your laptop, the project runs inside a pinned Linux environment. Here the image is amazon-amnesty:dev.

renv.lock

This records exact R package versions. Docker pins the operating system and geospatial stack; renv.lock pins the R package layer. Together they make the analysis reproducible.

Raw, intermediate, output

data/input/ is for source data or documented snapshots. data/intermediate/ is for generated files needed by later steps. output/ is for final tables, figures, and results. Mixing these up is how hidden dependencies appear.

Magic file

A magic file is an input that a script needs but no script in the repo produces and no documentation treats as a source snapshot. The main magic-file blocker right now is CleanCARShapes_robust/*.shp.

Difference-in-differences

A common economics design: compare how outcomes change before vs. after a policy for a group exposed to the policy, relative to a comparison group. Here, the comparison group must be chosen carefully because ineligible land-grabbers may change behavior if they expect future amnesty.

Raster vs. shapefile

A raster is a grid of pixels, like MapBiomas land cover. A shapefile is vector geometry, like parcel boundaries or conservation areas. Much of the project is overlaying rasters and shapefiles correctly.

Libraries and habits you will see in the R code

You do not need to become an R expert before helping. Learn the recurring tools enough to recognize their role, then deepen as you touch each script.

Spatial

sf

The core spatial library for vector data: shapefiles, polygons, intersections, coordinate systems, and spatial joins.

Data wrangling

dplyr, tidyr, purrr

These are the tidyverse tools for filtering rows, creating columns, grouping, joining tables, reshaping data, and repeating an operation over many files.

Paths

here and fs

These keep file paths relative to the project root instead of hardcoding /Users/... paths from someone else's computer.

Input files

readr, readxl, base R

These read CSVs, Excel files, and R-specific files like .rds and .Rdata. The best practice is to make reads and writes explicit.

Text cleaning

stringr and stringi

These normalize municipality names, accents, state codes, and other text fields so joins do not fail because of spelling or encoding differences.

Best habit

Small scripts, explicit outputs

Each migrated script should do one job, read known inputs, write known outputs, and be safe to rerun.

The blocker that matters most

Lots of files are messy. The big conceptual blocker is narrower: the CAR chain bottoms out on an undocumented cleaned shapefile set.

Recover or decide CleanCARShapes_robust

Legacy code combines Thiago's cleaned per-state CAR shapefiles, intersects them with the Amazon biome, and writes car_combined_amazonBiome2.shp. The cleaning step itself is not in the repo .

Possible resolutions

Either recover Thiago's cleaning workflow, accept the cleaned shapefiles as a documented source snapshot, or decide to skip that cleaning and build from raw SICAR shapefiles. Each choice changes the reproducibility story .

What to do while waiting

Migrate the independent MapBiomas backbone: MapBiomas TIFF plus Amazon biome border to grids, legacy forest, transitions, and transitions_combined .

What not to do

Do not wire downstream scripts by copying hidden outputs into place. That makes the repo look better while preserving the actual reproducibility problem .

Commands, without assuming you love terminals

You do not need to understand every flag. You do need to use the right entry points so the project runs in the reproducible environment.

Use these

The project command menu

make docker-build
make all
make docker-boot   # human interactive shell
make docker-run CMD="Rscript code/01_build/02_vtn/0_clean_muni_boundaries.R"
make docker-run CMD="make -f analysis.mk 02_vtn"
make docker-run CMD="make -f analysis.mk help"

make is just a shortcut menu. The Makefile hides long Docker commands behind memorable names .

Avoid these

They bypass or weaken reproducibility

Rscript code/01_build/02_vtn/0_clean_muni_boundaries.R
Rscript r-src/map_vnp_prices.R
docker run -it amazon-amnesty:dev bash
install.packages("newpackage")  # inside a running container

The first two run R on your laptop instead of inside Docker. The last one installs a package in a temporary container layer that disappears and is not recorded .

When a package is missing

The package dance

  1. On the host only: Rscript -e "install.packages('somepackage'); renv::snapshot()" .
  2. Rebuild the image: make docker-build .
  3. Verify in Docker: make docker-run CMD="Rscript -e \"library(somepackage); cat('ok\n')\"".
